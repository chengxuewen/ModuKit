# Dora (dora-rs) — External Reference Profile

> Research date: 2026-10-09 · Checkout: `.refinfo/dora` @ `8a8289c06` (2026-10-08, read-only clone)
> Upstream: `https://github.com/dora-rs/dora` · License: Apache-2.0
> External observation only — nothing here is ModuKit content (repo anti-pattern rule).

## 1. Portrait

Dora bills itself as an "Agentic Dataflow-Oriented Robotic Architecture" (README): a
100 %-Rust framework where an application is a **dataflow graph** of independent
**nodes** (one OS process each) exchanging typed, timestamped messages over topics,
orchestrated across machines. It is the closest live worked example of what ModuKit
Stage 2 becomes: multi-process plugins, a central coordinator, a distributed data
plane, and four language APIs hanging off one Rust core.

Scale: 6,036 commits since 2021-07-24; ~180k lines of Rust under
`libraries/ apis/ binaries/`; a 94-member Cargo workspace. Reached v1.0 on 2026-09-02
after a ground-up rewrite, and shipped v1.1.0 five weeks later (2026-10-07).
Commercially pushed by the founders through robotics demos (ROS 2 and MAVLink
bridges, camera/LIDAR nodes); the `dora-core`/`dora-*` namespace is a precedent for
ModuKit's own `modukit-*` plan (whitepaper §2.3).

## 2. Architecture (the part that matters to ModuKit)

### Coordinator + daemon + node model

Three-tier control plane, two-plane data path (README §Architecture, verified against
sources):

| Link | Mechanism | Role |
|---|---|---|
| CLI ↔ Coordinator | WebSocket, port 6013 | build/run/stop commands |
| Coordinator ↔ Daemon | WebSocket (postcard frames) | dataflow lifecycle, node spawn |
| Daemon ↔ Daemon | Zenoh overlay | cross-machine routing |
| Node ↔ Node | Zenoh **shared-memory** direct path | zero-copy data plane |
| Daemon ↔ Node | shared memory / TCP | control + small-message delivery |

- **Coordinator** (`binaries/coordinator`, state in `dora-coordinator-store` over
  `redb`): tracks daemons, distributes builds, survives restarts — daemons
  reconnect and the persisted store replays dataflow status.
- **Daemon** (`binaries/daemon`, one per host): spawns node processes, health-checks
  them (restart policies, `startup_timeout` watchdog), relays control messages, and
  hands nodes their Zenoh peer set so the data plane is peer-to-peer after join.
- **Node**: external process using a per-language node API (`dora-node-api`,
  `dora-node-api-c`, `dora-node-api-cxx`, `dora-node-api-python`).

**Two integration tiers — the Stage 1/Stage 2 answer in one product.** Besides
external nodes, dora runs **operators** *in-process* inside a shared runtime:
`binaries/runtime-shared-lib` loads `.so/.dll/.dylib` operators via `libloading` over
a C ABI produced by `safer_ffi` (`apis/rust/operator/types`), and
`binaries/runtime-python` hosts both Python operators and native ones from the wheel.
Operator = cheap function, node = isolated process, same topic contract. ModuKit's
"kernel + out-of-tree plugins" split maps onto this directly.

### Zero-copy shared-memory topics — what it actually is

The brief's "`dora-eyrc`" does not exist in this tree. History: dora once used
**iceoryx** and removed it deliberately (early PR #201 "remove-icoryx", #205
"remove-libacl which was required by Iceoryx"; `eyra`/`eyrc` appear in no manifest).
v1 zero-copy is **Zenoh `~1.10` with the `shared-memory` feature**
(`Cargo.toml:183`): payloads above `zero_copy_threshold` (default 4 KiB, env
`DORA_ZERO_COPY_THRESHOLD`) go through a Zenoh SHM pool (`DORA_NODE_SHM_POOL_SIZE`) on
the direct node↔node path; anything below, or on the daemon-routed path, is copied
under a 64 MiB frame cap. `SharedMemoryId` survives in `dora-message` only as the
daemon↔node small-message channel.

### Polyglot API surface strategy (the lesson)

One Rust core, four outward faces, deliberately asymmetric:

- **Rust**: full-fidelity API, thin wrapper over Zenoh samples + Arrow.
- **C**: a hand-maintained `apis/c/node/node_api.h` copied at build time (no
  cbindgen); C++ wraps it via `cxx`. Control-plane structs cross as flat C ABI.
- **Python**: `pyo3` behind `abi3-py311` wheel (`dora-node-api-python`), stubs
  generated by `generate_stubs.py`; `dora.start_runtime()` entry point embeds the
  native operator runtime inside the Python process.
- **Typed operators via `safer_ffi`**: Rust operators compile to C-ABI shared
  libraries the daemon can load — one implementation, ABI-mediated reuse.

This validates ModuKit's whitepaper stance ("bindings generated from one C ABI"):
dora reached the same shape, but hand-maintains the C header and pays for it (the
v1.0.1 `cargo package` incident, §7).

### Timestamp / ordering semantics

Every message is a `Timestamped<T>` whose stamp is a `uhlc::Timestamp` — a Zenoh-side
**hybrid logical clock** (`dora-message/src/common.rs`, HLC in
`apis/rust/node/src/event_stream/`). No bare wall clock in the data path. Ordering is
enforced per-input by the event-stream **scheduler**
(`apis/rust/node/src/event_stream/scheduler.rs`) with two queue policies
(`dora-core` config): `DropOldest` (default) and `Backpressure` (10× buffer, then
drop-with-error; since v1.1 a full backpressure input *blocks its producer* instead
of dropping). The scheduler refuses to evict messages carrying correlation metadata
(`request_id`/`goal_id`, service/action "patterns" like `service-server`) — dropping
one would hang a client forever. Replay correctness against clock jumps is explicit:
recording offsets are taken on the monotonic clock because "an NTP/GPS sync landing
mid-capture steps the wall clock" (`dora-recording` docs comment).

Topic payloads are typed: URNs (`std/core/v1/Float32`, nested/user types) from a
registry under `libraries/core/types/std/`, validated at build/`dora validate` time
(`input_types`/`output_types`, `strict_types`). Node metadata lives in the YAML
descriptor + JSON schema (`dora-schema.json`), not markdown — the Hub spec
(`docs/plan-node-hub.md`) explicitly calls out that "a node's inputs/outputs are
prose in a README" as the problem it fixes.

## 5. Highlights & Limitations

Highlights:
- A *shipped* multi-process plugin topology: coordinator/daemon split, per-host
  daemon, peer-to-peer SHM data plane, rolling-upgrade and version-gate machinery.
- In-process (operator/C ABI/`safer_ffi`) and out-of-process (node) tiers coexisting
  under one typed topic contract.
- HLC timestamps + per-input scheduler with correlation-aware eviction guards;
  replay-safe monotonic offsets.
- Exceptional changelog/upgrade-note discipline: every breaking change states the
  symptom, the mechanism, and the operator's action.

Limitations:
- Bus factor (§3): architecture knowledge concentrated in one full-time maintainer.
- Deep, load-bearing coupling to Zenoh internals (`unstable` feature flag on a
  released dependency; uhlc; SHM zAlloc) — a Zenoh breaking release is a dora
  breaking release.
- Transport semantics tangles: v1.1 had to *route backpressure inputs onto the daemon
  path, forfeiting zero-copy* (#3428) because the fast path shared one ingress channel
  with timer floods — performance and correctness paths diverge under stress.
- Two-week v1.0→v1.0.1 crate-publish breakage (§7) and multi-stage schema-version
  resets show a still-crystallizing release pipeline.
- Young v1 lineage: the pre-rewrite (0.x) community material describes APIs that no
  longer exist.

## 6. Historical Lessons (from changelog + git archaeology)

1. **Positional encodings punish absent schema-versioning.** v1 switched `bincode` →
   `postcard`; both are non-self-describing, so adding a field silently
   mis-decodes everything after it. The coordinator store's `SCHEMA_VERSION` had to
   be bumped 2→3→4→5 in months, twice as forced *data-rejecting* resets because an
   intermediate bump was forgotten (#2471: `DataflowStatus::Failed` gained a field
   with no bump; two mutually incompatible "schema 2" shapes on disk, failures
   swallowed at `warn!` level, failed dataflows vanished from `dora list`). Same class
   hit `.drec` recordings (v1→v2, no converter) and the WebSocket topic channel (now
   handshake-negotiated `protocol_version`). Lesson for ModuKit: choose
   self-describing or versioned-framed serialization from day one, and make decode
   failure non-swallowable.
2. **Their own semver gate leaked.** The `dora_version` register check used
   `VersionReq::parse("1.0.0-rc.4")` → `^1.0.0-rc.4`, which *matches* `1.0.0`:
   rc-era peers passed the gate and failed later in the frame decode. Mixed-version
   upgrades became an explicit documented hazard ("upgrade daemon and nodes together").
3. **The rewrite was codenamed "Adora"** (tag `before-adora` at 2026-04-17, branch
   tag `consolidation/v1.0-rewrite-detail`): ~4,900 commits consolidated, ~290k
   insertions to v1.0.0, then renamed back to `dora` (commit a288e8916: "resolve
   circular import after adora→dora rename"). Lesson: a greenfield rewrite kept
   shipping fixes on the old tree during consolidation, and the rename itself leaked
   into packaging.
4. **Workspace-local paths are not publish-safe.** `dora-operator-api-c`'s build.rs
   `include_str!("../node/cmake/…")` a sibling crate: fine in-tree, impossible from
   the crates.io tarball — v1.0.0 shipped un-installable, patched next day (v1.0.1).
5. **Coordinator restart raced its own data plane** (#2085): stopping a dataflow and
   respawning on Zenoh produced cross-daemon stale-traffic; the fix was a two-phase
   restart protocol — control-plane lifecycle must fence the data plane explicitly.
6. Validation gaps found the hard way: unvalidated `rev:` hashes became a path-escape
   in the clone cache (#3647); invalid timing fields *panicked a daemon, killing all
   its dataflows* (#3649); one bad `send_stdout_as` string silently killed a node's
   log task (#3643). All now rejected at validate/spawn time.

## 7. Value for ModuKit

**Verdict: ADAPT (strongest Stage-2 mirror in the scan).**

- **Stage 2 (multi-process + IPC)** — adopt the *shape*, not the bits:
  per-host daemon + global coordinator with persisted store; two-plane separation
  (WebSocket/postcard control vs SHM data); node-integration handshake with
  explicit version gate; health-check/restart-policy/startup-timeout watchdog;
  best-effort multi-daemon stop and fenced two-phase restart (their #2085/#2896
  outcomes are exactly the bugs ModuKit will otherwise rediscover).
  The operator-vs-node tier (one contract, C-ABI in-process and out-of-process) is
  direct input to the kernel+plugin design: keep the Stage-1 ABI close enough that
  a Stage-2 host can run Stage-1 modules in-process, the way `runtime-shared-lib`
  and `runtime-python` share `runtime-api`.
- **Transport fork (iceoryx2 vs Zenoh, whitepaper §5)** — dora is *evidence for
  Zenoh, with a caveat*: it started on iceoryx, removed it early (libacl/daemon-
  dependency pain, PRs #201/#205), and bet everything on Zenoh + its SHM transport,
  gaining the overlay/`unstable` coupling (§5 limitations). Its taught subtlety:
  **zero-copy is only the happy path** — routing for correctness (backpressure,
  small messages) silently forfeits it, so the transport choice must be made at the
  *semantics* level (who may block whom, which frames may drop) before the shared-
  memory layer. Read alongside the sibling `iceoryx2`/`zenoh` profiles before
  adjudicating.
- **Adopt outright**: HLC timestamps (`uhlc` is standalone), correlation-guarded
  scheduler with `DropOldest`/`Backpressure`, monotonic-offset replay rule, typed
  URN topic contracts + validate-at-expansion, the changelog/upgrade-note format,
  cargo-deny + git-cliff + cargo-dist tooling.
- **Adapt cautiously**: their polyglot face — a Rust-first API, one hand-maintained
  C header, pyo3/abi3 wheel — proves the single-ABI strategy works but predicts the
  drift bugs; ModuKit's generated-bindings plan should start from the lessons in
  #6.4/#6.5 rather than copying the manual header.
- **Avoid**: forking on top of `zenoh/unstable`; re-doing the pre-1.0 event-vocabulary
  churn — define the control-protocol enum once, with a schema-versioned frame
  envelope from commit zero.
- **License gate**: Apache-2.0 with a NOTICE file; compatible with ModuKit's license (TBD at profile time; D1 since)
  license and with relicensing into any permissive choice. No copyleft exposure.
  Safe to read, cite, and pattern-borrow; no code reuse planned yet.
