# Tutorial 06 - Script plugins

Python and JS programs can BE ModuKit plugins: the kernel spawns your
script as a child process across the exe wall (chapter 04), hands it a
control socket, and speaks a frozen wire protocol to it. You write a plain
script - stdlib only, no `.so`, no `LD_PRELOAD`, no npm - and a
hand-written skin (`bindings/py/plugin_runtime.py`,
`bindings/js/plugin_runtime.mjs`) walks the wire for you.

## The four hidden contracts

Read these BEFORE your first script plugin - all four are enforced or
verified by the door:

1. **The manifest `runner` must be an ABSOLUTE existing path.** Bare
   `python3` is refused (the executor resolves the runner literally -
   `crates/modukit-core/src/executor_proc.rs`; the leg wiring shows the
   shape at `scripts/demo-wave2-plugin-py.sh:103-116`).
2. **Your plugin must NEVER print.** The control socket IS fd 0; stdout
   and stderr are nulled - any print corrupts the wire. Quoted from
   `test-plugins/py/py_echo.py:4-6`:
   ```python
   # The kernel spawns it as `python3 <this-file> --fd=0` (manifest kind=exe,
   # runner=<absolute interpreter path>); the control socket IS fd 0 and
   # stdout/stderr are nulled - this file must never print.
   ```
3. **Out-of-tree scripts need `MODUKIT_PY_SKIN`** pointing at
   `bindings/py` (the staged file cannot reach the repo-relative default;
   quoted from `test-plugins/py/py_echo.py:24-28`). In-place checkouts
   resolve it without the env.
4. **The bindings are generated - DO NOT EDIT** (D63). Quoted from
   `bindings/py/modukit_embed.py:1-4`:
   ```python
   """Generated by modukit-codegen (wave-2 Python volume M1+M2, D100 R2-A) from
   modukit_embed.h. DO NOT EDIT - the contract ORIGINAL is the C header this
   floor mirrors; skins are generated FROM it (D63: hand-writing a replacement
   of this floor is forbidden).
   ```

## The shape (Python)

Quoted from `test-plugins/py/py_echo.py:85-90` - the whole activation is
one `serve` call:

```python
rt.serve(ID, VERSION, NAME,
         services={ID: ["echo", "caps", "seen"]},
         on_call=on_call,
         on_bus=on_bus,
         topics=topics)
```

The JS twin is the same shape in ESM, quoted from
`test-plugins/js/js_echo.mjs:86-94`:

```js
await rt.serve({
  id: ID,
  version: VERSION,
  name: NAME,
  services: { [ID]: ['echo', 'caps', 'seen'] },
  onCall,
  onBus,
  topics,
});
```

## The callbacks are where your plugin lives

The `serve` shape is the doorway; the callbacks are the plugin. The echo
implementation and the bus derivative, quoted from
`test-plugins/py/py_echo.py:59-76`:

```python
def on_call(method, inp):
    if method == "echo":
        return (0, inp)
    if method == "caps":
        return (0, b"\x01")
    if method == "seen":
        return (0, state["seen"])
    return (-1, b"")  # the child's own code is the unknown-method authority


def on_bus(topic, payload):
    state["seen"] = payload
    if topic == TOPIC and not state["republished"]:
        # Republish exactly once: the derivative rides the same topic and
        # re-enters through the same self-echo - an unguarded callback would
        # loop the start window against its own drain.
        state["republished"] = True
        rt.publish(TOPIC, payload + DERIV)
```

Two disciplines to copy: the unknown-method answer is YOUR code's
authority (a typed `(code, bytes)` pair, never a crash), and a callback
that republishes must guard itself - the comment names the loop it
prevents.

## Run the door (both languages)

```bash
bash scripts/demo-wave2-plugin-py.sh
bash scripts/demo-wave2-plugin-js.sh
```

The transcript proves, in order: a 14-golden-frame wire CONFORMANCE pass
with two hostile plants (before any launch), sup_install, FIDELITY (a
constant crosses byte-verbatim), capability caps, a BUS ROUNDTRIP (the
seed crosses out, the self-echo crosses back, the derivative is visible
via `seen`), a clean DIAL refusal with the child alive, a cooperative
STOP, the liar fixture answering typed `ServiceCallFailed` twice while
staying ACTIVE, then a driver SIGKILL and the `/proc` census = ORPHAN-
PROOF.

## The liar fixtures are the negative proof

`test-plugins/py/py_liar.py` / `test-plugins/js/js_liar.mjs` answer wrong
ON PURPOSE. The typed `ServiceCallFailed` - not a crash, not a hang - is
the liar family doing its job: a plugin that misbehaves gets a typed,
observable answer while staying alive for the census.
