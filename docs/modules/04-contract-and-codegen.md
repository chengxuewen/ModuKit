# 04 — Contract and Codegen: Single Source, Two Transports

D2/D4. One interface definition generates everything; the process boundary is not written by
hand any more than a language binding is.

## 1. Single source

The contract is authored **in `.proto`** (D13): one hand-written proto file per contract
package — messages, `service{}` blocks, `(modukit.*)` option stamps. From it, one `protoc`
run with our plugin yields:

| Output | For | When |
|---|---|---|
| local dispatch (message enum + direct call) | `dl` placement | Stage 1 |
| wire format (serde-framed messages + proxy/skeleton) | `exe` placement | Stage 2 |
| C-ABI function table (`repr(C)` vtable) + C header | native plugin authors — generated from the same `service{}` (D13; whitepaper §3.2 finally literal) | Stage 1 (shape), frozen later |
| per-language SDKs | Python/C#/JS/Lua... | authors read `.proto`+`fdset` day one; deeper SDKs Stage 5 |
| `SERVICE_ID` consts (canonical reverse-DNS, D9) | typed lookup keys + cross-check | Stage 1 (emitted into generated Rust skeleton) |
| topic schema types (D10) | recorder typing, bridges, late-join | Stage 1 in-proc; Stage 2 wire |
| **contract registry (D12/D13)** | `.proto` = authored original (repo); `fdset` = protoc-native ledger (machine consumers, repo) | Stage 1 (no exporter; golden-file tested plugin) |
| **typed data-plane view (D14)** | generated `meta` always-cheap + lazy `plane()/data()`; borrows = locality made honest | Stage 1 (Rust/C faces); SDK mirrors Stage 5 |

**Pipeline boundaries (D13 doctrine):** ① only cross-plugin contract types enter `.proto` —
kernel-internal types (state enums, config structs) stay hand-written Rust and are never
reverse-generated; ② the generated trait skeleton *is* the contract surface (impl is by
hand); skeletons land in `OUT_DIR` — the only repo originals are `.proto` + `fdset`;
③ transport remains our TL frames/slots — rejecting gRPC/tonic was about the substrate,
never about the `.proto` authoring.

The dispatch enum is placement-agnostic: `dl` executes it in-process without serialization;
`exe` serializes the same enum over the wire. **Local transport may skip serialization but
never the message shape** — shape divergence is what would make 01's switchability a lie.

## 2. Message shape rules

- Arguments/returns are owned values (`Vec<u8>`, `String`, serde'd structures), never
  references or trait objects crossing the boundary.
- Buffers above a threshold travel as **fd / shared-memory handles** passed via the transport
  abstraction, not byte-copy through the control channel (the stage-2 SHM decision sheet in
  `docs/reference/00-overview.md` §2 attaches here).
- Every call carries the registration id + method id; streams/callbacks are modeled as
  registered service references (consumer side) rather than raw function pointers, keeping
  cross-boundary calls symmetric.
- **Synchronous boundary, explicit asynchronous** (D6): contract methods either return
  `Result<T>` directly (short work) or a **job token** (long work, 02 §4). No language-level
  `async`/`await` crosses the boundary — a C ABI has no runtime to await on. Per-language
  async surfaces are runner-side sugar generated above the same message shape; the costed
  precedent for fighting this is uniffi's async-across-FFI machinery and its partial
  withdrawal (`docs/reference/uniffi-rs.md:85-96`).
- The `exe` wire transport is internally message-passing with id-correlated
  request/response (the LSP/Wayland shape) — actor mechanics as *transport*, never as user API.
- **Three registry rules (D12, non-negotiable):** ① hand-written field numbers in
  `.proto` from day one (positional encoding is the dora failure class — dora.md:166-171);
  ② unknown fields must decode-and-skip; ③ unknown enum variants map to a declared
  sentinel. `fdset` is regenerated by CI and diffed against the checked-in copy (empty diff
  or red); plugin output is golden-file tested; the contract suite runs against generated
  skeletons.
- **Bulk framing — the sidecar rule (D12):** a batch payload riding a frame stream (no pool
  slot) carries metadata in the proto envelope and Arrow IPC bytes as the *final* opaque
  field — header first, tail never parsed (the technique Arrow Flight ships in production;
  its gRPC substrate is deliberately NOT adopted — D6 sync boundary holds). Below ~1KB
  everything stays ordinary encoded envelope; bigger belongs to the cargo lane.
- **Two-stage retrieval (D14):** the generated interface exposes metadata as a plain
  field (a few bytes, inline, always available) and data as a lazy accessor — borrowed
  view in-host, owned bytes across hosts. The split is the API-level fuse against
  accidental whole-cargo copies; recorder copy-counters can name offenders.
- **Cargo is binary in shape (D15):** descriptor-class cargo appears in exactly one `oneof`
  with two arms — `local{slot,epoch,layout}` (same-host ticket; bytes stay in the pool) or
  `tail` bytes (off-host; cargo rides the waybill at the largest field number). Generated
  accessors branch internally; callers see one `plane()/data()` surface. Pixels never enter
  `.proto` — the type face describes, the ticket locates, the deployment sizes (08 §2).

## 3. Handshake and guards (`dl`, and the same fields over `exe`)

At resolve the host reads, without executing plugin code:

```
modukit_plugin_init -> *const PluginAbiV1 { abi_version, size, name, start, stop, ... }
```

- **Version integer + struct size** are both checked before any call. (CLAP carries version in
  the first field of an exported global struct — `docs/reference/clap-plugin-abi.md:26-37`;
  one integer compare is the whole negotiation. rutis' lesson is the negative: treating a
  successful `dlopen` as a compatibility test is declared as its own anti-goal —
  `docs/reference/rutis.md:109,183-184`.)
- Unknown major version -> `FAILED` at `RESOLVING` (03 §1), never a partial start.
- **Descriptor cross-check (D7)**: self-reported fields (`id`, `version`, provides/requires
  summary) are compared against the deploy manifest at resolve — mismatch fails resolution
  before any call (05 §6). This is what licenses the boot graph to trust the file tier.
- Symbol discipline: single exported entry symbol (`modukit_plugin_init`); plugin internals stay
  private; edition-2024 `#[unsafe(no_mangle)]` + `extern "C"` on the entry only.
- Pre-load validation exists for hostile shapes: ELF/Dylib sanity checks before executing
  initializers (rutis metadata-first argument — `docs/reference/rutis.md:183-184`; header-first
  vs metadata-first itself remains a queued canon question, architecture.md §11).

## 4. Contract suite

One suite, two placements (01 §3): a fixture plugin must pass the same behavioral tests via
`DlopenExecutor` and (from stage 2) via the shadow-runner. The suite lives in the kernel repo;
third-party plugins may run their own copy against the SDK. The kernel-v0 experiment proved the
harness shape (cdylib artifacts are built inside the test explicitly — a `cargo test` subtlety,
not a design fact).

## 5. What is NOT here yet

External C-ABI surface freeze (export header versioning policy), cbindgen/uniffi integration
choices, runner SDK generation, capability negotiation vocabulary. All sit in the §11 queue of
architecture.md; none of them change the object model above.
