# Skill Authoring (this workspace)

## Overview

- One skill = one directory under `.agents/skills/<lower-kebab-name>/` with a
  `SKILL.md` entry point. The directory name is the skill name.
- `SKILL.md` frontmatter is the registry source: `name`, `description`, `type`,
  optional `notes`, and `status` when the skill is inoperative or deprecated.
- `SKILL.md` at the repo root is GENERATED by `pixi run agents sync`; never
  hand-edit the registry table or the generated `AGENTS.md` regions.
- `.agents/skills/` is the only editable copy. Host layers
  (`.codebuddy/skills`, future `.trae/skills`) are generated links or copies.

## When to Use

- Adding a new project skill.
- Changing a skill's trigger/description or its body.
- Retiring a skill: mark it `inoperative`, or make it a deprecated alias that
  points at the replacement; do not delete silently.
- Reviewing whether a host actually receives a skill.

## Process

1. **Name**: lower-kebab, unique, verb-oriented where possible
   (`code-review-and-quality`, `skill-authoring`). The directory name must equal
   the frontmatter `name`.
2. **Frontmatter**:
   ```yaml
   ---
   name: <directory-name>
   description: "<what it does>. Use when <trigger>."
   type: process|tooling|reference
   notes: "<short routing note>"
   ---
   ```
   Keep `description` under 1024 characters; put routing triggers there, not in
   a second table.
3. **Body**: purpose, when to use, process/checkpoints/exit, anti-patterns.
   Keep the file under 800 lines. All prose is English (C1).
4. **Optional metadata**: `.skill_id` only when a host or registry needs it.
5. **Registry**: run `pixi run agents sync`; it adds the row to `SKILL.md`.
6. **Lint and gates**:
   ```bash
   python3 scripts/skill-lint.py
   pixi run gate-skills
   pixi run gate-agents
   ```
7. **Host activation**: `pixi run agents sync` also creates/updates the enabled
   host layers. CodeBuddy gets a relative symlink under `.codebuddy/skills/`;
   Windows uses `--copy`. The host must be restarted or reopened to see a new
   skill.
8. **Inoperative / deprecated**:
   - `inoperative`: keep the directory and say why in `notes`/body; do not route
     to it.
   - `deprecated alias`: keep the directory, name the replacement, and never
     add a second routing table.
9. **Exit**: `skill-lint` 0 fail, `gate-skills` green, `gate-agents` green,
   `git ls-files -ci --exclude-standard` empty.

## Anti-patterns

- Hand-editing `SKILL.md` registry rows or `AGENTS.md` generated regions.
- Copying a skill into a host directory by hand; fix the generator instead.
- Two skills with the same name or two skills claiming the same trigger.
- Adding a skill whose body is longer than the 800-line limit.
- Leaving an inoperative skill unmarked; the next reader will route to it.
- Adding a `CODEBUDDY.md` or a second skills target file to make one host work.

## Rationalizations

| Excuse | Rebuttal |
|---|---|
| "I'll add the registry row later" | `gate-skills` reds now; run `agents sync` in the same change. |
| "The host will pick it up automatically" | Host layers are generated at session start; sync, then reopen the host. |
| "A copy is simpler than a link" | Copies drift; links/copies are generated and guarded from one source. |
| "This skill is old, delete it" | Mark it inoperative or a deprecated alias; deletion loses the routing record. |
