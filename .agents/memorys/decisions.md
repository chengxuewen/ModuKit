# ModuKit — Decisions

> Format per `.agents/rules/common/lesson-memory.md`: `## D{n}: <title>` + decision + rationale + reference (source, date).

## D1: Project license = MIT OR Apache-2.0 dual (2026-10-09)

- **Decision**: dual license `MIT OR Apache-2.0`. Full texts at repo root (`LICENSE-MIT`, `LICENSE-APACHE`); the Cargo workspace sets `license = "MIT OR Apache-2.0"` under `[workspace.package]` once it exists (Stage-1 trigger); generated binding artifacts ship under the same dual. Contributors must DCO-sign (`git commit -s`) from the first external contribution.
- **Rationale**: embeddable-SDK form (hosts include closed commercial HMI/cockpit software per README/whitepaper positioning) requires non-viral terms; the Apache leg carries a patent grant + termination clause (real SEP exposure in automotive/industrial); the MIT leg covers GPLv2-only and NOTICE-averse legal contexts. Ecosystem default (serde/tokio/wasmtime/iceoryx2 all same dual) = zero downstream surprise. Reference-series evidence: `docs/reference/ctk.md` (Qt LGPL runtime burden), `zenoh.md` (EPL users switch to the Apache leg), `uniffi-rs.md` (MPL discourages enterprise vendoring).
- **Rejected**: MIT alone (no patent clause); Apache alone (strictly narrower — loses MIT-only scenarios); MPL/EPL (weak copyleft conflicts with embed-anywhere doctrine); GPL/AGPL or open-core commercial now (no monetization mandate in canon; the OSS dual grant keeps a future commercial layer additive, not revocable).
- **Reference**: user approval "luodi/landed" 2026-10-09 (chat); sibling precedents .refinfo/VisiaEngine (same dual), MediaServo (Apache-only).
- **Re-review triggers**: (1) a GPL-family dependency becomes a required vendoring; (2) commercial dual-licensing initiative opens; (3) first external contribution lands (verify DCO tooling is live).


## D2: Unified plugin model — placement is a deployment property (2026-10-10)

- **Decision**: one plugin abstraction; executors form a closed set {dl, exe, wasm}; language lives on an orthogonal runner axis (generated SDKs, never new core mechanisms). A plugin ships one `.so`; `dl`/`exe` chosen at deployment via shadow-runner (generic runner dlopens the same artifact in a child). Switching is a tested property (five preconditions + CI dual-placement suite); crash blast radius and cost asymmetries are documented, never hidden. `exe -> dl` is vetoed by trust tier.
- **Rationale**: maintainer adjudication 1 in an options walkthrough; industry convergence (dora operator/node same-contract, ipc-channel inprocess+cross-process backends, CLAP handshake, VST3 Gateway/ROS2 components); device-access shape still uncertain, so the placement axis must stay open.
- **Reference**: `docs/modules/01-plugin-placement-model.md` + `docs/architecture.md` §4; `docs/reference/dora.md:48-52`, `ipc-channel.md:14,96`, `clap-plugin-abi.md:26-37`.
- **Re-review triggers**: first vendor SDK needing isolation (shadow-runner build-out); any plugin failing the exe-placement suite (preconditions too loose/strict); wasm executor arrival.

## D3: Availability grade — in-vehicle B tier, no hard real-time (2026-10-10)

- **Decision**: state machine gains a `Failed` edge with manifest-declared restart policy (backoff/cooldown/max); start levels + parallel dependency-respecting boot; per-dependency consumer policies `wait|failfast|fallback`; required deps validated at resolve; high-rate hardware data planes bypass the plugin bus entirely (orchestration only).
- **Rationale**: adjudication 2; A tier (desktop) cannot honor the crash-restart promises without plugin-API rework later; C tier (safety-adjacent) belongs to system layers, not a framework; D (silent defer) rejected as API-liar discipline.
- **Reference**: `docs/modules/03-lifecycle-state-machine.md`; `whitepaper.md:226` (staged-delivery risk clause); `zellij.md:63-64` (contained-crash presentation).
- **Re-review triggers**: a hard boot-deadline requirement lands on ModuKit (it should not — system-level early apps own that); watchdog/ASIL contract with a real safety vendor.

## D4: Service model — C+ (static binding + dynamic events + six invariants) (2026-10-10)

- **Decision**: dependencies declared in manifest (`required|optional`, `on_down`); typed queries + snapshot/delta event stream; six B-compatible invariants (handles-not-instances, registration ids, case-insensitive properties map, reserved ranking, snapshot+events, acquire/release call shape). LDAP/Tracker/Factory/leases/lazy-activation explicitly unimplemented with structures reserved.
- **Rationale**: adjudication 3 rejected both extremes — static-only cannot model the crash-restart reality D3 promises; full OSGi dynamic has no production precedent across a process wall (CppMS itself declares "no remote story", `cppmicroservices.md:80`) and taxes every consumer; the user's "get it right in one shot" was answered by making the *object model* one-shot (§3 invariants), not the vocabulary.
- **Reference**: `docs/modules/02-service-model.md`; `cppmicroservices.md:30-38,80`; `ctk.md:79` (15-year edge-case ledger).
- **Re-review triggers**: first external (non-kernel) plugin consumer — invariant list is unverified until then (adjudication 4 declined the early-consumer round; logged risk); any need for multi-instance ranking semantics.

## D5: Stage-1 scope — solo+AI thin-edge cut (2026-10-10)

- **Decision**: year-1 builds only: state machine (with Failed/policy types), manifest v0, C+ registry, contract codegen v0 (Rust-only, local transport, locked shapes), DlopenExecutor (parked kernel v0 + three surgery points: executor seam, Failed edge, message-shaped API), dual-executable test suite skeleton. Explicitly out: ProcessExecutor impl, bindings, compositor, SHM plane, C-ABI export freeze, watchdog, OTA, CLI.
- **Rationale**: adjudication 4 (builder mode A, demo-driven); the reference-project origin accounts (CppMS 14y, CTK 15y, dora 5y/6036 commits) show full-OSGi semantics are multi-decade products; thin edge + correct structure is the only schedule that survives solo+AI; whitepaper §9 demands staged delivery.
- **Reference**: `docs/architecture.md` §10; `cppmicroservices.md:9`, `ctk.md:79`, `dora.md:16-17`.
- **Re-review triggers**: app team forms (schedule the declined external-consumer validation round); beachhead demo date becomes binding.

## D6: Async model — synchronous boundary, explicit jobs, event completion (2026-10-10)

- **Decision**: contract methods return `Result` directly or a `JobToken`; long work completes through the registry event stream; `cancel(token)` is a message. No language-level async/await crosses the ABI or the process boundary. The kernel is runtime-agnostic (supervision on std threads; plugins own private runtimes). The `exe` wire transport is internally id-correlated message passing (actor mechanics as transport, never user API). Per-language async surfaces (Rust await sugar, Python asyncio, JS promises) are generated runner-side above the same message shape.
- **Rationale**: adjudication 5 (continued walkthrough). Physics: a C ABI has no runtime to await on — every surviving cross-boundary plugin ABI (COM/WinRT `IAsyncInfo`, VST3/CLAP callbacks, script-engine hosts) is a sync surface + explicit async objects; uniffi built the dedicated async-across-FFI machinery and later withdrew async constructors from Kotlin/Python (`docs/reference/uniffi-rs.md:85-96`) — the costed counter-example. Cross-process protocols (LSP, Wayland, gRPC) win via message-id correlation; the exe transport adopts that internally while users keep direct calls (pure-actor API rejected: learning cliff, structural channel tax, conflicts with D4 handle model). Shared-host-runtime poisoning (full-async option) is unacceptable for a cockpit main loop; a blocking `dl` plugin cannot be preempted — recorded as the honest asymmetry (modules/03 §5) with the job pattern removing the motivation to block. Withdraws the assistant\'s pre-written "Async-first" line in modules/04 §2 (self-audit: Rust-ergonomics bias, never adjudicated).
- **Reference**: `docs/modules/04-contract-and-codegen.md` §2; `docs/modules/02-service-model.md` §4; `docs/modules/03-lifecycle-state-machine.md` §5; `docs/reference/uniffi-rs.md:85-96,204`, `ipc-channel.md:93-94`, `zellij.md:63`; industry shapes COM/WinRT/VST3/LSP/Wayland (general knowledge, not repo-verified).
- **Re-review triggers**: first UI plugin needing backpressure beyond job tokens; volume of Rust-side ergonomics complaints after three internal plugins; component-model futures at the stage-5 wasm executor.

## D7: Manifest three-tier residence + cross-check (2026-10-10)

- **Decision**: deploy tier = external per-bundle `modukit.toml` (ops fields: placement floor, raise-only overrides, start_level/timeout, restart policy, consumer policies, capability requests, min_host); self-report tier = `PluginAbiV1` descriptor fields (id, version, provides+ranking, requires summary — script runners self-report on behalf of their payloads); verification tier = rutis-style pre-dlopen binary parse, stage-5 only, guard not truth source. Resolve enforces deploy<->self-report agreement (liar fixture in the contract suite). Single format TOML; JSON rejected as policy debt. Boot dependency graph builds from the deploy tier alone with zero code loaded.
- **Rationale**: adjudication 6. Each mainstream residence exists because the others hurt somewhere (CLAP hurts boot scanning, external files hurt truthfulness, embedded hurts ops and cannot exist for script plugins); the tier split assigns each pain to its correct layer and welds the lying gap shut with the cross-check. Queue item "header-first vs metadata-first ABI" (docs/reference/00-overview.md §4) narrows: manifest residence is decided, the question survives only for C-ABI surface generation.
- **Reference**: `docs/modules/05-manifest-and-deployment.md` §6; `docs/modules/04-contract-and-codegen.md` §3; `docs/reference/rutis.md:106,183-184`; `clap-plugin-abi.md:26-37,58`; `cppmicroservices.md:9`; `whitepaper.md:65,114`; VST3 scan metadata / OSGi MANIFEST.MF (general knowledge, not repo-verified).
- **Re-review triggers**: first untrusted third-party plugin (builds the verification tier); script-runner SDK pass (defines how runners self-report); marketplace tooling needing machine-readable metadata beyond TOML.

## D8: Update semantics — stop-based + declared parallel escape hatch (2026-10-10)

- **Decision**: year-1 update = stop-based: `dl` stages the new artifact and activates on next host boot (dlclose is not a reload strategy); `exe` swaps during the supervisor's STOPPING->STARTING cycle under restart policy. Consumers see exactly one Unregistered->Registered pair; gap tolerance is the already-adjudicated on_down/policy vocabulary. Author-declared `parallel_ok` services (stateless/idempotent claim, cross-checked between manifest tiers) may later run two versions concurrently in exe placement with version-affinity re-acquire and drained unregister — the declaration field ships inert in year 1; routing is a Stage-2 mechanism. OTA distribution stays outside the kernel. No new states enter the machine.
- **Rationale**: adjudication 7. Full OSGi-style rewire (dual-version always-on) was rejected as the ecosystem's historically hardest, most-often-skipped machinery and conflicts with the single-instance handle world of D4; plain stop-start would strand any service that truly cannot gap. The declaration route puts the risk decision where the knowledge is (author), limits blast radius to stateless services, and costs zero new year-1 structures — version/ranking properties and event streams from D4 already carry the load. Closes the whitepaper §4.1 "update" promise gap against modules/03 (self-found inconsistency; doc-audit class).
- **Reference**: `docs/modules/03-lifecycle-state-machine.md` §6; `docs/modules/02-service-model.md` §5; `docs/modules/05-manifest-and-deployment.md` §6; `whitepaper.md:111`; `clap-plugin-abi.md:37` (init-twice hazard history — why in-place dl reload is not pretended to work); OSGi rewire difficulty (general knowledge, not repo-verified).
- **Re-review triggers**: first service with a hard zero-gap update requirement (exercises parallel_ok early); Stage-2 exe placement build (routes version affinity); marketplace/OTA design pass.

## D9: Service identity — canonical reverse-DNS ids, consts, sugar-only aliases (2026-10-10)

- **Decision**: the true service key is a canonical reverse-DNS string (CLAP id grammar) carried in registration `properties` under `service.id`; versions never embed in the name (invariant 3). Rust plugins get `const SERVICE_ID` (proc-macro `#[modukit_service("...")]` sugar may follow; v0 hand-writes the const). Manifest short names resolve through bundle-scoped `aliases` at parse time — nothing downstream (cross-check, wire, ABI, registry) ever sees a short name. The cross-check (D7) compares canonical strings only.
- **Rationale**: adjudication 8. Short names collide without governance once a marketplace exists; Rust type paths let refactors change protocol identity and are meaningless to non-Rust runners (violates the two-axis model D2); bare reverse-DNS is ergonomically hostile. D9 composes the ergonomic wins of all three while keeping one canonical truth per boundary: reverse-DNS governance (CLAP-proven, `clap-plugin-abi.md:58`), macro ergonomics, alias sugar confined to the manifest parse scope.
- **Reference**: `docs/modules/02-service-model.md` §1; `docs/modules/04-contract-and-codegen.md` §1 (codegen row); `docs/modules/05-manifest-and-deployment.md` §3; `docs/reference/clap-plugin-abi.md:58`; OSGi class-name service keys and their refactor breakage (general knowledge, not repo-verified).
- **Re-review triggers**: first cross-vendor namespace collision report (governance rules may need reservation policy); runner SDK pass (alias handling must stay parse-side); marketplace naming policy design.

## D10: Topic bus — second object kind on the unified handle foundation (2026-10-10)

- **Decision**: cross-plugin communication is one object table with four handle kinds (service, job, topic, descriptor); what crosses any boundary is schema-shaped data, a numeric handle, or an OS descriptor — never a pointer, never a language future. Topics: named canonical ids, typed by the same single-source schemas, per-topic QoS (`latest-value` default — cockpit signal model; `keep-all | lossy(n) | bounded(backpressure)`), three commandments (no request-response, no cross-publisher ordering unless declared, slow subscribers never push through publishers). Registry and bus share snapshot+delta late-join semantics. Year 1 ships the in-process bus only; cross-process arrives through the D11 seam. Recorder/debugger are ordinary bus subscribers (`export`-gated), so recording and inspection add no mechanism. Manifest declares publish/subscribe; cross-check (D7) covers the topic summary.
- **Rationale**: adjudication 9 + the substrate survey (Mojo pipes / Wayland registry+fd / FIDL channels / gRPC inproc / ROS2 typesupport all converge on handle+message+descriptor+one-schema; OSGi EventAdmin proves service-only bus emulation regrows a bus; dora proves named typed streams carry a dataflow host — dora.md:11-13). With D4/D6/D9 already speaking that substrate, topics are not a second concept but the second object kind of one table.
- **Reference**: `docs/modules/06-topics-and-bus.md`; `docs/modules/02-service-model.md` §1; `docs/modules/04-contract-and-codegen.md` §1; `docs/modules/05-manifest-and-deployment.md` §3/§6; `docs/reference/dora.md:11-13`; `whitepaper.md:113`; Mojo/Wayland/FIDL/EventAdmin (general knowledge, not repo-verified).
- **Re-review triggers**: recording/replay pass; cross-process bus build exercising QoS against a real wire; multi-machine topic federation (Stage 4).

## D11: Transport architecture — narrow seam, per-plane slots, bridges not heart-swaps (2026-10-10)

- **Decision**: the kernel owns communication semantics (D10 object table, D9 naming, TL-versioned frames, descriptor kinds); middleware vendors are swappable only behind a ~10-method transport backend trait (frame movement + descriptor negotiation + capability probe + a permanent dummy test double). Slots are per-plane and simultaneous: local frames/pool (year 1: socketpair+memfd self-built; stage 2: vendor-pool decision open per 00-overview §2), remote carrier (zenoh-shaped), streaming link (WebRTC stage 4). Foreign middleware (ROS2/DDS/SOME-IP/existing zenoh meshes) interop as bridge plugins: opt-in export/import lists, per-bridge type-mapping and QoS translation tables, copy boundary — zero-copy never crosses a bridge; default is export nothing. The upgrade to a broader middleware abstraction is triggered only by an OEM contract demanding native graph visibility, and is then answered with a bigger bridge, never a core swap.
- **Rationale**: adjudication 10. rmw proves what happens when a whole middleware worldview is abstracted (least-common-denominator + N bridges). iceoryx2 itself abstracts only OS primitives (`-cal`, iceoryx2.md:37) and its cross-host story is a pluggable carrier shipping zenoh as the factory one (iceoryx2.md:39); zenoh self-limits local zero-copy (>4KiB out of the shm path); dora all-zenoh was the retreat counter-example; industry interop is bridges (zenoh-bridge-ros2dds, iceoryx2 gateway/adapter — general knowledge/WIP respectively). Solo+AI budget: one 10-method trait + dummy beats N worldview bridges by orders.
- **Reference**: `docs/modules/07-transport-architecture.md`; `docs/reference/iceoryx2.md:36-39,47`; `docs/reference/zenoh.md:33,36-40`; `docs/reference/00-overview.md` §2 (form adjudicated, vendor open); `ipc-channel.md:96` (dummy-backend doctrine); rmw history + ROS2 typesupport (general knowledge, not repo-verified).
- **Re-review triggers**: OEM native-graph requirement (big-bridge build); first cross-machine topic link; stage-2 pool backend selection (decision sheet).

## D12: Contract registry — Rust+prost authoring, derived sidecar/fdset, two-lane payloads (2026-10-10)

- **Decision**: single authority = derived registry pair — human-reviewable sidecar `.proto` + machine-readable `fdset` — emitted by our exporter from Rust sources; hand-edit forbidden; CI regen-diff gate; exporter round-trip joins the contract suite. Authoring stays Rust (`#[prost(tag="n")]` explicit field numbers from day one). Three registry rules: tags mandatory; unknown fields decode-and-skip; unknown enum variants map to a sentinel. Envelope lane = protobuf (params/errors/tokens/<1KB); cargo lane = Arrow first (sidecar framing: bill of lading first, IPC bytes last, tail unparsed; raw fd/DMA for media planes; fbs as trigger-based third cargo for heterogeneous zero-read). Scalar whitelist inherits AUDESYS D12's closed 14 (11 scalars + String + Blob + Array subset-mapped onto protobuf scalars, mapping table lives in modules/04). Multi-entry doctrine: year 1 = ONE door (Rust); `.proto` door (external authors, per-interface ownership via registry `owner` field) opens only on first external interface proposal; WIT door at Stage 5 — registry format never changes across doors. Escape hatch recorded: C -> B promotion (sidecar becomes source) is free; reverse is not.
- **Rationale**: adjudication 11 walked against B/A/D/E variants (E = AUDESYS-copy: its zero-read gold lives in the cargo lane; its hand-written-serialization debt and registry-less single-door model are rejected; its 14-type discipline is absorbed as whitelist). User-supplied corroboration during final round: Arrow Flight = production proof that "proto for metadata, Arrow IPC bytes as opaque tail for data" is the official complementarity pattern (sidecar zero-copy technique adopted; gRPC substrate explicitly NOT adopted — D6/D10 doctrine). Transcoder libs noted as bridge-side conveniences with self-reported, unverified benchmarks.
- **Reference**: `docs/modules/04-contract-and-codegen.md` §1-2; `docs/modules/06-topics-and-bus.md` §2; `docs/modules/07-transport-architecture.md` §2-3; `docs/reference/dora.md:166-171` (positional-encoding disaster), `dora.md:60-71` (sample+Arrow dual form), `whitepaper.md:176` ("no codec"); Flight/ptars/pybufarrow/arrowpb (industry knowledge from user-supplied material, not repo-verified).
- **Re-review triggers**: first bulk columnar topic (activates Arrow cargo); slot ③ implementation day (sidecar framing vs TL framing benchmarked against real traffic); recorder/replay (ruling 12) embedding fdset headers; first external interface proposal (opens the `.proto` door + `owner` enforcement); Stage-5 WIT projection; wire-encoding benchmark day once real payloads exist (prost measured vs alternatives).

## D13: Contract authoring door — hand-written .proto as single source; protoc plugin emits Rust/C ABI/fdset (2026-10-10)

- **Decision**: entry point = one hand-written `.proto` per contract package (messages + `service{}` + `(modukit.*)` stamps). A protoc plugin (the only custom codegen piece; golden-file tested) emits: prost message structs, Rust trait skeletons with `SERVICE_ID` consts, C header + vtable, and `fdset` (protoc-native `--descriptor_set_out`, no exporter). Repo originals = `.proto` + `fdset`; generated skeletons live in `OUT_DIR`. Doctrine: ① only cross-plugin contract types enter `.proto` — kernel-internal types stay hand-written Rust, never reverse-generated; ② transport stays our TL frames/slots (gRPC/tonic rejection targeted the substrate, not the authoring); ③ generated trait IS the contract, impl is hand-written. Revises D12's "Rust door + multi-entry" authoring clause; D2-D12 content survives untouched.
- **Rationale**: maintainer diagram challenge ("entry should be the human-authored proto; tooling generates Rust"). Flip moves the custom-risk surface from a fragile reverse exporter (parse own Rust+attributes -> emit standard; uniffi had to build heavy metadata plumbing for the Rust-source road — uniffi-rs.md:85-96,190-193) to standard forward codegen (protoc-plugin pattern, two decades of industrial groove, deterministic AST input). Bonus: fdset obtained natively; the C ABI — the whitepaper's sole cross-language exit — generated from the SAME source as the Rust face (§3.2 finally literal); Python/external authors stand at the front door day one (the "Rust barrier" concern dissolved by removal). Costs: boundary types authored in a ~50-rule DSL (D6/D2 flattening doctrine already made Rust type power non-portable across boundaries, so the loss is ergonomic, not expressive); build pipeline grows protoc+plugin (mise/deny pinned).
- **Reference**: `docs/modules/04-contract-and-codegen.md` §1-2 (pipeline + boundaries); `docs/modules/05` §6 (ledger cross-check); `docs/modules/06` §2 (topic stamps); `docs/architecture.md` §5/§10-11; `docs/reference/arrow-flight.md` (proto-authoring precedent); `uniffi-rs.md:85-96,190-193` (the costly alternative); `dora.md:166-171` (why hand-numbered tags stay).
- **Re-review triggers**: a kernel-internal type appears in `.proto` (boundary erosion — fix by rule, not exception); tonic/gRPC proposals citing "we already use proto" (answer: substrate rejected stands); protoc version upgrades shifting golden files en masse; plugin complexity outgrowing skeleton emission (signal we are accreting a dialect — reopen the DSL-vs-proto question honestly).

## D14: Descriptor access protocol + carrier-transparent API charter (2026-10-10)

- **Decision**: descriptor tokens are self-sufficient — envelopes carry `slot/epoch/layout`, readers compute addresses without any per-frame query. The pool fd transfers exactly once at subscribe-resolve via UDS `SCM_RIGHTS` (slot ① remains the only fd courier, D7); consumers mmap once, hot path = offset arithmetic + one atomic release. Liveness is typed, not documented: in-host views are borrows (Rust `FrameView<'a>`/Drop, C view+release pair, Python memoryview scope); stale tokens return `EPOCH_EXPIRED` as an ordinary error (never UB); process death auto-reclaims holds via the UDS-disconnect mechanism shared with the supervisor. Generated data-plane views implement two-stage retrieval: `meta` cheap-inline-always vs lazy `plane()/data()` (borrowed locally, owned bytes across hosts) — the API-level fuse against accidental whole-cargo copies. Carrier selection (SHM-first on-host / compressed line / WebRTC / zenoh) is a manifest-side deployment property; the `.proto` type side declares only `encoding` (what the cargo IS), never transport (how it moves). Cross-host zero copy explicitly stops at the host boundary.
- **Rationale**: maintainer's round-15 consolidation — "define once; language interfaces hand me metadata and data directly; locality invisible." Adopted as-is plus three honesty riders (latency→deployment/QoS surface, lifetime→types, loss→uniform Err set). It is the natural top story of the already-adjudicated building block pile (D2 shape lock, D7 fd doctrine, D10 commandments, D11 seam, D12 sidecar framing) — zero new mechanisms, all wiring.
- **Reference**: `docs/modules/07-transport-architecture.md` §3-4; `docs/modules/04-contract-and-codegen.md` §1-2 (view row + two-stage rule); `docs/modules/05-manifest-and-deployment.md` §6; `docs/modules/01-plugin-placement-model.md` §4 (asymmetry table, API edition); `dora.md:60-62` (threshold-split precedent), `iceoryx2.md:36-39` (pool semantics), `arrow-flight.md` §3 (sidecar).
- **Re-review triggers**: GPU/dmabuf slots (layout → offset/modifier; first real GPU composition lane — UI research track revival); stage-2 remote views landing (owned-vs-borrow duality documented in SDK guides); copy-counter telemetry showing `plane()` every frame (fuse not educating — revisit naming/defaults); pool backpressure semantics chosen at slot ② vendor decision (00-overview §2).

## D15: Cargo oneof — two arms, three-sheet definition law, bridge ticket-to-tail (2026-10-10)

- **Decision**: every descriptor-class payload type is ONE `.proto` message whose cargo appears in exactly one of two `oneof` arms: `local{slot,epoch,layout}` (same-host ticket; bytes stay in the pool, delivery is a 16B reference broadcast) or `tail` bytes (off-host; cargo rides the waybill at the largest field number — the sidecar streaming order, tag 1000). Generated views expose ONE accessor (plane()/data()) that branches internally; the frame object owns the ticket-or-buffer, inner views borrow from the frame itself, and the frame's destructor releases (atomic refcount / free). Bridge exchange: at host exit, a kernel thread rewrites local->tail (one honest copy; line compression = deployment axis, encoding = type axis, never conflated); no ticket ever crosses a network. Three-sheet law: the type face (.proto) says what cargo IS, the ticket (runtime) says where it IS, deployment (pool geometry cell_bytes/depth + routes) says how big/where-bound; pixels never enter .proto. EPOCH_EXPIRED is a normal outcome under LOSSY video QoS (slow readers fast-forward, never block the camera). Language-face honesty: Rust enforces the borrow rule by lifetime, C++ by RAII + debug asserts, C by release pairing — one ledger, three manners; no exceptions across the ABI, Result structs everywhere.
- **Rationale**: maintainer-approved consolidation of the walkthrough's final rounds (verdict: feasible, land it). The two-arm oneof is the minimal mechanical form of the agreed API-transparency goal: shape differs, acquisition identical, lifetime visible (D2 honesty doctrine applied at the type level). The three-sheet law kills the recurring "where is the frame actually defined" confusion (raised twice in-session). Tail-at-tag-1000 matches the Flight precedent (arrow-flight.md §3) while the ticket arm extends beyond Flight's vocabulary into our pool lane.
- **Reference**: `docs/modules/08-end-to-end-walkthrough.md` (worked example); `docs/modules/04-contract-and-codegen.md` §2; `docs/modules/07-transport-architecture.md` §3-4; `docs/modules/05-manifest-and-deployment.md` §6; `whitepaper.md:176` ("no codec" local path); `dora.md:60-62` (threshold split precedent); `arrow-flight.md` (sidecar ordering).
- **Re-review triggers**: first GPU/dmabuf frame path (ticket grows offset/modifier semantics; pool geometry per allocator); C++ false-positive debug asserts in real plugins (consider safe-handle mode); remote-leg ergonomics pressure at Stage-2 (optional "re-materialize as remote pool cell" policy — the D15 inbound default stays tail-only until measured).

## D16: Recording & replay — subscriber doctrine, three-part header, virtual-publisher replay (2026-10-10)

- **Decision**: the recorder is an ordinary, `export`-gated bus subscriber (modules/06 §3 doctrine upheld; a deep-kernel pre-QoS probe is explicitly REJECTED): files carry a three-part header (fdset copy + manifest snapshot + host/ABI stamps) making archives self-describing a decade later; records store waybill + payload bytes exactly as delivered (never re-encoded, tail-skippable per sidecar order); LOSSY drops surface as a separate gap-statistics stream (honest absence). Recording policy: default nothing (allowlist mirrors bridge export gates); dual-encoding doctrine separates archive quality from delivery degradation; full-rate raw is opt-in with an explicit MB/s budget table. Replay = virtual publisher re-entering identical envelopes (consumers cannot tell replay from live); clocks `realtime|burst|step`; content deterministic, timing explicitly NOT (monotonic-offset rule; capture_ts preserved); burst feeds the contract suite as fixtures. Container: mcap-first (verified at adoption), own TL-framed format as fallback; record model container-agnostic. Year 1 = design record only; implementation + dependency land with Stage 2.
- **Rationale**: adjudication 12. The recorder is the acceptance test of the ledger+bus+cargo-oneof trio — if public API can't do it, something was wrong. ## D31: Resource tree - directory-as-route, manifest-resident checklist, TOML (2026-10-10)

## D33: Language strategy - three layers, one dividing line (2026-10-12)

- **Decision**: languages split by WHO authors the execution artifact, not by syntax. (1) **Handwritten languages** (Lua/LuaJIT, JS/TS via QuickJS, Python via CPython/PyO3): authors write text, engines execute - exe-hosted runners per D2 (semi-trusted tier), no determinism promise, no runner ordering - each triggered by the first real plugin need; the shadow-runner skeleton is extracted when the second runner lands (not before). TS is a development-time language compiling to JS; no separate runner, ever. (2) **Generated/graph languages** (IEC 61131-3: ST/IL/LD/FBD/SFC, plus future blueprint and G frontends): authors draw/design, machines emit execution artifacts - ALL lower to the AUDESYS hal-ir VM (bridged, same-maintainer asset: hal-ir 2,560 lines with 20-opcode VM, five compiler frontends ~5.7k lines, gcode too). The scan cycle maps to the D20 step clock (determinism become promiseable). The VM is plain Rust and can compile into the wasm executor - making industrial DSL programs the ONLY DSL path into the untrusted/wasm tier (script engines cannot follow: LuaJIT has no wasm target). (3) **Blueprints** = generalized FBD frontends emitting the same IR (FBD is industrial blueprint; fbd-compiler 532 lines is the codegen reference). Script downgrade (graph -> Lua/TS text) is an editor EXPORT option for readability, never the execution route. Never: self-built script engines, a general-purpose ModuKit VM, or the full LabVIEW scheduler. G-language scheduling fears are resolved the same way (dataflow -> IR, timing structures -> step clock); G remains the most distant trigger (market-driven only). wasm component model stays the terminal scaling path for handwritten-language breadth (new languages = new compile targets, not new runners).
- **Rationale**: adjudications from the polyglot brainstorm, corrected twice in discussion. First correction: AUDESYS already BUILT the IR path (hal-ir + five IEC frontends measured in .refinfo/AUDESYS), so "never build DSL runtimes" became "bridge the family asset - zero compiler cost, five languages arrive at once". Second correction (maintainer challenge): with layer 2 existing, blueprints downgrading to Lua/TS lost their only real argument (VM cost); the dividing line moved to authorship - human-written text runs on engines, graph-authored programs lower to IR, because graph users read the diagram, not the artifact (UE users never read blueprint bytecode). Performance analysis: the IR choice for layer 2 is justified by PROMISEABLE determinism (fixed instruction count, no GC pauses vs 30-100x engine slowdown missing 1-10ms scan deadlines), not raw speed.
- **Reference**: `.refinfo/AUDESYS/crates/` measured: audesys-hal-ir (2,560 lines: 20 opcodes, vm.rs 506), audesys-hal-binding-gen (2,599: ST frontend), il-compiler/ld-compiler (1,899), fbd-compiler (532, cascade-downgrades-to-IL), sfc-compiler (751), gcode-compiler (same HalProgram target); D2 (runners, trust tiers), D6/D20 (sync boundary, step clock = scan cycle), D13 (proto door unchanged - IR programs are payloads, not contracts), wasm tier (D2 executor set); LuaJIT-no-wasm-target / UE-blueprint-VM / LabVIEW-G-scheduler (general knowledge).
- **Platform matrix (adjudicated same day)**: two artifact forms only - native engine (exe-runner) and wasm component/IR; platform reach follows artifact form. Full-platform lines (native + wasm tier + browser): TS/JS (dev-time TS compiling to JS in browsers natively; to wasm components via jco/ComponentJS when untrusted), Rust/Go (native dl / components), industrial DSL (hal-ir VM native on step clock, VM@wasm in the sandbox). Native-only lines: Lua (LuaJIT - no wasm target exists, plain-Lua@wasmoon would forfeit JIT and fork the engine) and Python (CPython/PyO3 - Pyodide is a 10-20 MB second-start engine, never a plugin path). Priority order adjudicated: JS/TS and wasm-component support first; Lua/Py cross-platform explicitly deferred - wasmoon/Pyodide revisited only if a real need materializes (trigger below); untrusted Lua/Py demand redirects to TS/JS or Rust components; browser page authors may embed anything, but ModuKit does not provide/test/support script engines in wasm (three-nos).

## D34: Shutdown budget + host lifecycle (2026-10-12)

- **Decision**: two rulings from the lifecycle-coverage audit (votes C, C), plus seven consistency patches. (1) **stop_timeout** (05 §2): every plugin gets a per-plugin shutdown budget (default 2s, manifest-configurable); on expiry the outcome follows the D2 placement asymmetries exactly - exe = SIGKILL the process (that is what isolation is for), wasm = cancel execution (engine epoch interruption), dl = mark FAILED and move on (in-process code cannot be killed; the host never lets one plugin block the shutdown sequence; dl state consistency on expiry is best-effort by design). (2) **Host lifecycle** (03 §7 new): cold start = observation ring first (D19), deploy-TOML (D29), boot DAG (03 §3); graceful shutdown = SIGTERM/SIGINT -> reverse start_level stop with per-plugin stop_timeout -> host-level total budget, exceeded = unclean exit code; **self-healing belongs to the OS** (systemd Restart= / vehicle supervisor) - the host cooperates with an exit-code vocabulary (clean/config/fatal) and best-effort crash testament (last N ring events persisted; implementation trigger-gated). External watchdogs stay out of scope (03 §4 unchanged). (3) **Patches**: capability set frozen at install, no runtime revocation, restart IS revocation (05 §2); duplicate-id double-bundle install rejected at staging, supersession = UPDATE (05 §2); reverse-order shutdown made explicit (03 §7); publisher-side rate limits not built year 1, enforcement trigger-gated on first topic storm (06 §5); same-machine multi-host discovery rides the zenoh carrier on loopback - no separate local-discovery mechanism ever (07 §2); service-level access control named in Deliberately-not, trigger = first multi-vendor ecosystem (02 §5); hot-update state handover explicitly undefined, year-1 update is cold-state stop-then-start (02 §5).
- **Rationale**: adjudications 29-30 walked one-by-one from the lifecycle/governance audit (the user asked "anything missed?"). The audit grid was the full OSGi-Compendium set x automotive-SOA checklist x the 33 existing rulings: most rows were already covered; the two real holes were the shutdown budget (a hung stop() would hang the whole power-down sequence - safety-grade in-vehicle) and the host's own lifecycle (the most deployment-load-bearing implicit contract, same vacuum shape that produced D29). ## D35: Boundaries - gates/audit split, no gateway, cluster identity (2026-10-12)

- **Decision**: three positioning rulings from the governance/gateway/discovery/cluster brainstorm (votes C, C, C). (1) **Gate/audit split** (02 §1): policy checks stay at their own gates (install = bundle integrity D28; resource window = path+capability D30; executor = trust tier D2; direct calls = no extra hop), while every allow/deny decision lands as an ordinary event on the observation ring (D19) - audits are pure walks over the ring (D17). Cross-tier call direction unrestricted; callbacks INTO a lower tier pass that tier's capability gate. The unified policy-engine point was rejected (per-call hop taxes D6, single point of failure, wrong abstraction for differently-shaped gates - the service-mesh sidecar lesson). (2) **No gateway** (07 §5 terminology): plugin-to-plugin = direct calls; foreign middleware worlds = bridge plugins of any size (DDS gateway precedent, identity always a plugin under D26); external entry points = bridge plugins too; central traffic policy = deploy more bridges, never a kernel component. (3) **Cluster identity** (01 §6): every machine's host fully sovereign (autonomy = partition resilience); cross-machine access rides the carrier with local-identical syntax (D14); fleet orchestration (placement, version consistency, rolling updates) belongs to the orchestrator (vehicle SM / K8s-class), with ModuKit cooperating via the deploy manifest (packaging unit) and the idempotent install protocol (D28). No logical multi-machine host, no placement scheduler, no split-brain semantics - refused as identity-level scope.
- **Rationale**: adjudications 31-33 walked one-by-one. The recurring pattern: each buzzword (governance, gateway, discovery, cluster) maps to either an already-adjudicated mechanism restated, or a term discipline that prevents future re-litigation. Observability without gateways rides the ring (D19/D21/D18/D16/D17/D32): per-plugin flight recorders instead of door counters; multi-machine observability is sink topology, not infrastructure.
